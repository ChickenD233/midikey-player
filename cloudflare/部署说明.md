## 一、先明白你要做什么

部署完之后你会得到一个网址，长这样：

```
https://midikeyplayer-sync.你的名字.workers.dev
```

这个网址要内置进程序。所有用户都连它。

**它是公共的**，你只需要部署一次。用户不用注册、不用装任何东西。

## 二、方法一：从 GitHub 自动部署（全程在网页上点）

你的程序已经在 GitHub 上，用这条路最省事。

1. 打开 <https://dash.cloudflare.com/>，注册或登录。免费账号就行，不用绑卡。
2. 左边选 **Compute (Workers)** → **Create** → **Workers** → **Import a repository**。
3. 第一次会要你授权 Cloudflare 读 GitHub。点 **Add Git account**，按提示走完。
4. 选中仓库 **ChickenD233/midikey-player**。
5. 在构建设置里填两样：
   - **Root directory（根目录）**：`cloudflare`
   - **Build command（构建命令）**：留空
   - **Deploy command（部署命令）**：留空
6. 点 **Deploy**。

Cloudflare 会读 `cloudflare/wrangler.toml`，建好房间对象，然后给你那个网址。

以后要改中转站：你 push 到 GitHub，Cloudflare 自己重新部署。

> 这一步我只核对过 Cloudflare 官方的 Git 集成说明，没有实际跑过。
> 如果界面上找不到某一项，告诉我，我按你看到的界面再校对。

## 三、方法二：用命令行部署（作者走的就是这条）

需要电脑上有 Node.js 18 或更高版本。

```bash
cd cloudflare
npm install            # 只做一次
npx wrangler login     # 会打开浏览器让你授权，只做一次
npx wrangler deploy
```

最后一条命令跑完会打印你的网址。

实测输出（作者部署时）：

```
Durable Object exports reconciliation:
  Created: Room
Uploaded midikeyplayer-sync (3.62 sec)
Deployed midikeyplayer-sync triggers (2.34 sec)
  https://midikeyplayer-sync.dl18710255985.workers.dev
```

看到 `Created: Room` 说明房间对象建好了。

## 五、怎么用（普通用户看这里）

**普通用户什么都不用配。** 程序里已经内置了作者的中转站地址。

1. 每个人先各自导入同一首 MIDI 文件。
2. 房主：设置 → 实验功能 → 填「我的名字」、「房间名」、「密码」→ 点「创建房间」。
3. 房主：点「复制邀请串」，把那一整行发给朋友。
4. 朋友：粘进「加入房间」，点「加入」。
5. 每个人勾自己的声部。
6. 所有人点「我就绪了」。
7. 房主点「开演」。倒数 3 秒后全场一起开始。
8. 之后房主可以「暂停 / 继续 / 跳转 / 停止」，也可以「统一为这个值」把移调同步给全场。

邀请串长这样：

```
mkp://midikeyplayer-sync.dl18710255985.workers.dev|小明的琴房|mypassword
```

### 想换成自己的中转站

1. 按第二或第三节部署，拿到你的网址。
2. 设置 → 实验功能 → 展开「高级：中转站地址」→ 填你的网址。
   开头不用写 `https://`，结尾不用写斜杠。
3. 想让它成为所有用户的默认值：把网址写进 `Engine/SyncModel.cs` 的
   `DefaultRelayHost`，重新发版。

## 六、花费

免费额度（Cloudflare 官方数字）：

| 项 | 免费额度 |
|---|---|
| 请求 | 每天 10 万次 |
| 计算时长 | 每天 13,000 GB-秒 |
| SQLite 存储 | 5 GB |

这个中转站没有心跳、没有轮询。一场 5 人 1 小时的演奏约 50 条消息，
按 WebSocket 消息 20 比 1 折算，约等于 3 次请求。

另外用了 WebSocket 休眠 API：房间里没人操作时，对象会被换出内存，不计计算时长。

所以正常使用远达不到免费额度。要花钱只可能是被人恶意刷。

### 实测时延

作者的机器到 Cloudflare 边缘，60 个样本：

| 项 | 实测 |
|---|---|
| 最快 | 42 毫秒 |
| 中位 | 43 毫秒 |
| 最慢 | 49 毫秒 |
| 抖动（中位绝对偏差） | 1 毫秒 |

另外两项：

- 一个完整来回（成员 → 服务器 → 房主）：约 109 毫秒
- 加密连接建连：125 到 574 毫秒（首次要 TLS 握手，之后是长连接）

倒数 3 秒的余量是 43 毫秒的 60 倍以上。所以网络快慢基本不影响对齐。

## 七、出问题怎么查

| 现象 | 先查什么 |
|---|---|
| 程序说"连不上中转站" | 浏览器打开 `/health`。看不到 ok 就是没部署成功 |
| `/health` 打得开但程序连不上 | 网址填错了。不要带 `https://` 与结尾斜杠 |
| 提示"密码不对" | 房间第一次创建时用了哪个密码，后面就得用哪个。房间名也参与校验，改房间名等于换房间 |
| 提示"房间满了" | 一个房间上限 32 人 |
| 提示"发得太快" | 10 秒内超过 60 条消息会被断开。正常使用碰不到 |

Cloudflare 后台可以看到实时日志：**Workers & Pages** → 你的 Worker → **Logs**。

## 八、中转站里存了什么

| 存了 | 没存 |
|---|---|
| 密码的 PBKDF2 派生值（不存明文，也不存可反推的值） | 明文密码 |
| 成员名单（名字、声部、移调、是否就绪） | 明文房间名 |
| — | 曲子、按键、任何音频 |

房间名不进网络：客户端按房间名算出一个键，键放进连接地址，服务器只看到键。

成员名单在最后一个人离开后留在 SQLite 里。要清掉就在 Cloudflare 后台删掉 Worker，
或者改一次房间名（等于换了一个对象）。

## 九、在本机先试一遍（不用 Cloudflare 账号）

想先确认中转站本身没问题，可以在本机跑：

```bash
cd cloudflare
npm install          # 只做一次
npm run dev          # 起本机中转站，地址 http://127.0.0.1:8787
```

另开一个窗口跑联调脚本。它用真的 WebSocket 客户端连上去，跑一遍完整协议：

```bash
cd cloudflare
npm test
```

期望看到 `结果：20 通过 / 0 失败`。它验的是：

- 建房与加入，密码不对被拒
- 成员名单与声部、移调、就绪状态的广播
- 开演（含房主的单调时刻）、暂停、停止、统一移调
- 不认识的消息类型被静默忽略
- 断线后名单更新

**也可以拿它测云端**：

```powershell
$env:RELAY_URL="wss://你的网址.workers.dev"
node test-relay.mjs
```

本机联调走明文 `ws://`。程序检测到回环地址（`127.` 或 `localhost`）会自动用明文，
正式部署的地址一律走 `wss://`。

## 十、文件说明

| 文件 | 作用 |
|---|---|
| `src/index.js` | 中转站本体 |
| `wrangler.toml` | 部署配置。声明房间对象与存储类型 |
| `test-relay.mjs` | 联调脚本。本机实例与云端地址都能测 |

不用改 `src/index.js` 与 `wrangler.toml` 就能用。
